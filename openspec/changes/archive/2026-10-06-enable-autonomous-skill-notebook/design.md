## Context

动机见 [proposal.md](proposal.md)。本次基线是当前工作树：已有的按需状态查询改动尚未提交，但必须保留，不回到旧常驻面板。四份 delta specs 分别约束发现、写入、审查和维护。

当前关键路径：

- `src/context.ts` 的指导只有搜索/读取职责；`src/catalog.ts` 已支持名称与描述关键词搜索、范围和来源类别筛选。无需新增搜索引擎。
- 前台 `hermes_skill_manage` 和后台审查通过 `src/index.ts` 的提交路径进入 store；`ManagedSkillStore.submitModel` 也使用 `assessContent`。当前 `src/content.ts` 只给来源摘录及单一流程模板自动内容证明，其余正文和资产进入内容 pending。
- `src/permissions.ts` 的版本 1 状态只有全局布尔授权与 pending；具体批准绑定完整 preview 的 hash，提交时重新检查来源与版本。归档、恢复和回滚另有授权入口，不能只改普通更新而留下旁路。
- `src/ui.ts` 使用前台稳定结束后的单一调度路径，当前缺省开关按 false 处理；`src/ledger.ts` 保存显式选择、费用、暂停与预留。

## Goals / Non-Goals

**Goals:**

- 在既有提交链上允许可追溯的 AI 自由归纳，将“这是模型笔记”与“是否可以修改该文件”分开处理。
- 用户仅在手装内容确需授权时做决定；通过自然名称和摘要选择，不用复制内部标识或日常处理受管内容审批队列。
- 明确区分用户拒绝、保持原版转写、实际保存与尚需继续提炼，避免把意图或模型回答当作完成。
- 兼容现有状态和恢复依据，所有模型调用继续经过原有费用与资格门禁。

**Non-Goals:**

- 不新增可选审查模型、跨模型 digest、完整 Hermes cache-parity fork 或缓存命中保证。有关 Hermes 配置的问答不扩大本 change；当前模型及完整有效快照策略保持不变。
- 不新增技能关系数据、向量库、强制笔记加载、后台多轮工具 Agent 或独立整理服务。
- 不新增自动过期归档或永久删除。既有显式合并、归档、恢复和回滚继续保留，普通笔记修订不要求运行这些高级命令。
- 不改 memory 插件、用户已安装副本、个人状态或账本；不包含提交、发布和真实付费测试。

## Decisions

### 1. 自由归纳是一种记录类型，不是新的事实认证

在现有内容来源记录中加入 `agent-notes` 类型，普通模型提案默认使用这条路径：保留完整的名称、描述、正文和合法支持文件，记录绑定当前有效证据的引用及来源角色。结构、非空有效证据、作用域、文件限制和版本仍由宿主校验；没有证据不是“交给人工批准就算有效”的替代路径。

保留显式的来源摘录、旧模板以及历史 `user-approved`、`restored-version` 的读取与兼容，不再使用措辞白名单决定通用笔记是否自动接受。自动保存的来源记录表明内容由 AI 归纳，不能将其转换为 confirmed 成功统计或新的运行授权。提示要求区分已观察结果、来源报告和建议，宿主不声称能够确定性证明任意自然语言结论。

统一修改两个 `assessContent` 使用路径及公开工具/审查输入约定，防止前台可保存而后台仍被旧模板拦截，或底层路径接受缺证据内容。历史 pending 不因新政策自动重放。

**取舍：** 不引入第二个模型判断正文正确性，也不继续把自由笔记全部交用户审稿；代价是笔记可能归纳错误，通过来源、按需读取、后续纠正及历史恢复处理，而不是虚称事实认证。

### 2. 一份用户策略，覆盖所有手装写入口

将现有 agentDir 权限状态升级为版本 2：`policy: ask | allow | notes-only`、以现有稳定 SkillId 标识的允许集合，以及原 pending。集合对应具体来源/作用域/项目身份，不按显示名称、目录前缀或包名批量授权；不把版本 hash 作为长期白名单键，因为合法更新会改变版本。

判定顺序：当前来源和身份检查 → managed 自主写入，或 user-owned 的白名单 → 全局策略 → 询问模式下的本次精确批准；确定保存目标后，对实际写目标执行全部 pin、只读、路径和版本保护。原技能只读或 pinned 禁止修改原件，但不禁止读取当前允许的内容并保存到另一个可写受管目标；来源被排除则不能绕道读取。全局切到 notes-only 后，旧的一次批准不能越过新策略写原件，只有有效白名单优先。对 user-owned 的归档、恢复、回滚也查询同一策略；notes-only 对不能转写为笔记的位置操作明确阻止，不能把“保存了补充笔记”当作完成归档/恢复。显式维护保留其差异及恢复交互，不把每次低使用量判断变成自动改动用户技能的授权。

所有授权只由真实用户设置入口或真实 TUI 决定创建，模型提案不能提交 policy/allowlist。使用现有锁和原子状态写入；保存前在 writer 授权检查中重新读取许可，并沿用来源回调和版本比较。始终允许后若文件已变，白名单可保留用户刚授予的未来许可，但本次旧差异必须报冲突，不能声称已经更新。

**取舍：** 不增加互相竞争的 YOLO/拒绝布尔开关、持久拒绝黑名单或通配授权。仅一个三态默认值和一份具体允许集合。

### 3. 四个选择替代普通手装更新的二选一审批

复用当前公开 Pi UI 的精确逐成员差异审阅方式，冻结展示的 preview；随后给出：

| 文案 | 结果 |
| --- | --- |
| 允许本次修改 | 仅提交当前目标、版本和展示差异，不持久扩大权限 |
| 始终允许修改此技能 | 保存具体白名单许可，再尝试同一份差异 |
| 本次不修改 | 终止该提案，不自动转存这项被拒绝内容 |
| 保留原版，记入 Hermes 笔记 | 原件不写；将本次改进交给受管笔记流程，不改变全局策略 |

取消、关闭、编辑了审阅载荷或生命周期已失效时都不写入、不添加白名单。当前交互轮次内记住被拒绝的目标，防止模型换个措辞立即再次询问；这不是持久黑名单，用户明确重提可再次处理。

前台正常请求直接使用该交互。后台不抢占正在执行的前台任务：先保留有界 pending，在下一个真实 TUI 的安全前台交互点提供待决选择；同一轮不反复弹出已取消或拒绝的请求。Print/RPC 不因 `hasUI` 或假确认取得批准，保留结构化结果与按需查询入口。旧 `/hermes-skills pending/approve/reject` 继续用于高级处理，不成为普通 managed 笔记的必经流程。

增加按需 `/hermes-skills settings` 入口：选择三态全局模式、查看和移除允许技能；常规添加由“始终允许”完成。旧 `installed allow/deny` 保留为明确用户命令别名，分别映射 allow/ask；原非 TUI 的显式确认规则保留。状态查询展示策略及允许集合，但不常驻显示。

**取舍：** 不制作新的常驻仪表盘，不要求用户为每条笔记学习命令，也不为普通文字归纳新增一次内容审批。

### 4. 转写是 Agent 的普通笔记工作，不是复制原技能或关系维护

前台管理工具遇到 notes-only 或第四种选择时返回结构化的转写结果：原件保持不变、当前改进和适用范围、搜索已有受管笔记的指引。Agent 在当前正常工具交互中先搜索，再读取目标版本，更新已有笔记或创建新的笔记。没有受管候选时不能机械复制整个原技能作为“补充”。

后台审查前向同一请求提供可信的当前策略摘要；只需覆盖当前涉及技能，不注入整个白名单。对于当前快照已读原技能，可用已有本地名称/描述搜索补充有界受管候选元数据；不读取全库正文，不做额外模型检索。附加材料纳入同一请求的输入估算和准入，不裁剪完整有效快照来腾出空间。更新仍需要实际已读正文和成员版本；缺少这些信息时返回转写待继续，由前台正常读取和提炼，不凭候选名称直接覆盖内容。

已准入请求能提出有效受管候选时，按普通 managed 路径提交；否则如实报告待继续或无保存。选择第四项只创建本地转写决定，不触发一次新的辅助审查。原始收费记录、用量和终态不因后续本地批准被伪装为另一项完成；本地提交有自己的现有变更记录。若一个改进同时带有原件和替代候选，只选择一个目标路径，提交时仍重验最新政策和资格。

笔记在 `name` 或 `description` 中包含原技能名称及适用任务词，正文解释前提；不新增 `parentId`、`relatedSkillId` 等字段，也不强制命名后缀。权限及一次操作的目标 ID 不是笔记关系。保持搜索现有的空白分词、大小写不敏感包含匹配，不把它描述为语义或正文检索。

**取舍：** 不为了后台一次必须完成而追加请求或丢掉未读内容。一次结果可能需要前台继续，但用户不用手工抄笔记或维护关联表；真正保存与待继续在结果中明确区分。

### 5. 只改变缺省值，不重置开关、调度和账本

集中计算有效自动开关：读取到合法状态后，缺少 `autoEnabled` 才采用 true；已有 true/false 原样保留。读账本失败、损坏或已初始化文件丢失不是“未设置”，仍阻止收费。项目根选择和状态显示也使用同一有效值，不在其它入口通过 `?? false` 隐式写回关闭，也不覆盖已有 false。

保留当前 10 个工具模型轮次的触发门槛、独立用户轮次计数、前台 idle/settled 检查、快照去重与生命周期取消。默认开启不意味着加载就调用、每个任务都调用或退出前额外 flush。显式 disable 持久生效；resume/ack 不更改 enable、不释放 unknown 预留。

费用保持：单请求输入 64000、输出 4096、90 秒；每 agentDir 的 UTC 日 4 次、256000 输入、16384 输出，并发 1；项目只能收紧。所有附加指导、证据和候选材料均参与估算，UTF-8 估算不是实际账单。迟到 usage 只归回原请求，不恢复写入资格或改写终态/原因；超出预留重新暂停。不增加自动重试、换模、子进程兜底或验证模型。

前台管理工具自身不创建额外辅助模型请求，但主 Agent 的正常对话与工具后续轮次仍有自身 token 成本，不能宣传为免费学习。与 memory 的可选协调继续沿用原协议；不把未验证的真实互操作说成已经支持。

**取舍：** 不引入首次使用费用弹窗或按技能学习开关，遵循已确认的默认自动学习；用现有硬预算、持久关闭/暂停以及按需费用查询提供控制。

### 6. 日常修订与高级维护分开

主代理指导和后台指导都要求先复用、再修订、最后才新建，保留适用范围、失败原因和有用步骤，而非追加日志。相同问题的新证据更新既有受管笔记；原 skill 更新不触发自动全库关系扫描，Agent 后续读取时按实际内容纠正自己的笔记。

已有 semantic-curation 仍是显式的一次计费任务；归档逐成员、共享引用不移动、邻居不动、恢复不覆盖手改、partial 不假装原子回滚等不变。新内容记录类型须贯通历史、恢复及维护读取，不能靠删掉旧保护测试让自由笔记路径通过。

**取舍：** 不另建自动整理流水线；优先在现有写入、搜索与恢复机制上完成日常自主修订。

## Risks / Trade-offs

- 自由归纳不保证正确 → 明确为 AI 笔记，保留真实来源和版本；不增加语义认证模型或伪造 verified 标签。
- 元数据关键词可能漏搜、产生语义重复 → 名称/描述包含原技能和任务词，先搜后写，保留现有重复检查；不承诺关系图或语义搜索级的完整召回。
- 后台没有读到合适的既有正文 → 明确返回待继续，前台正常工具链读取后提交；验收同时覆盖可完成正例和此受限结果，不能用全部待继续冒充学习成功。
- 默认开启增加请求机会 → 保留原预算与所有失败暂停，旧 false 不升级成 true；用确定性 provider 验证派发与费用，不擅自运行真实付费验证。
- 多写入口遗漏新权限策略 → 对普通更新、支持文件、归档、恢复和回滚做交叉矩阵；来源失效或撤权在提交前再次检查。
- 新权限格式不能直接交给旧版本使用 → 新版读旧版、未知版本拒绝写入，保留状态备份；不通过删除权限或账本文件降级。
- 四选项和待决交互可能打扰或误显示完成 → 只在安全真实 TUI 交互，拒绝去重，关闭不授权，状态区分意图与已提交结果；无常驻面板。

## Migration Plan

1. 在隔离测试 agentDir 中覆盖空白、缺省、显式 false/true、暂停、unknown 预留和损坏状态；项目运行目录及用户真实数据不作测试夹具。
2. 版本 1 权限读取为兼容的逻辑视图：true → allow，false → ask，白名单为空；新空白状态为 ask。通过既有锁和原子写入持久化版本 2，完整保留 pending、applying 和 failure，不执行它们。
3. 不批量重写现有 skills 或历史 proof，不迁移已安装原件，也不创建笔记关系。新受管写入记录新内容类型，旧记录照常读取与恢复。
4. 同时交付有效开关、策略、前后台指导和相关回归，避免出现“默认已开但自由笔记仍全部 pending”的中间产品状态。文档明确升级保留已有关闭，实际安装/重载由后续明确操作处理。
5. 回退前通过新版显式关闭自动审查并保留完整状态备份；旧版不能识别新权限格式时保持拒绝写入，不清空/降级成默认许可。技能内容恢复继续使用现有版本检查；不得覆盖之后的人工修改。旧版兼容迁移若另有需要，应单独明确范围，而不是自动丢弃白名单或后来新增的记录。

## Verification Approach

验收矩阵覆盖：两条提案路径的自由笔记正例与非法证据负例；三策略 × 白名单命中/不命中；四个决定及取消/冲突/撤权；真实 TUI 与非 TUI；新旧开关和费用暂停；按原技能名称发现并再次更新受管笔记；不新增关系文件或后台请求。继续运行现有类型检查、完整测试和严格 OpenSpec 验证，并复核安静 UI、恢复与统计的旧断言。

确定性/SDK 测试证明的是流程和计费边界，不证明真实模型长期学习质量、真实账单或 memory 插件真实联合运行。交付证据分别列出已跑范围、未跑实模范围和残余限制，不以旧测试数量、规划完成或追溯健康代替新实现验收。
